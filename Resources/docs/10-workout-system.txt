=====================================
1. PURPOSE
=====================================

This document defines the complete workout system for FitOnus, covering the exercise library, workout plan creation, AI-generated workouts, active workout tracking with live set/rep logging, rest timers, workout history, personal records, and progressive overload recommendations. The workout system is one of the most interaction-intensive features in the app and must deliver a seamless, gym-floor-ready experience.

=====================================
2. OVERVIEW
=====================================

The workout system consists of five interconnected subsystems:

  1. Exercise Library — A comprehensive database of categorized exercises with descriptions, muscle group targets, equipment requirements, and difficulty levels.
  2. Workout Plans — Templates defining a sequence of exercises with prescribed sets, reps, rest periods, and progression rules. Can be created manually, generated by AI, or selected from curated templates.
  3. Active Workout Tracking — A real-time workout session interface with exercise navigation, set logging (weight + reps), rest timer, and performance feedback.
  4. Workout History — Complete log of all completed workout sessions with performance metrics, trends, and personal records.
  5. AI Workout Generation — Personalized workout plans generated by the AI Coach based on user goals, equipment, available time, fitness level, and recent training history.

=====================================
3. GOALS
=====================================

  - Provide a workout tracking experience comparable to dedicated fitness apps (Strong, Hevy, JEFIT).
  - Enable users to create, follow, and track workouts without leaving the app.
  - Deliver AI-generated workout plans that adapt to user progress and preferences.
  - Track progressive overload (increasing weight, reps, or volume over time).
  - Detect and celebrate personal records (PRs) in real time during workouts.
  - Support offline workout tracking (gym environments often have poor connectivity).

=====================================
4. FUNCTIONAL REQUIREMENTS
=====================================

  4.1 Exercise Library
    - Browse exercises by muscle group (chest, back, shoulders, arms, legs, core, full body).
    - Browse exercises by category (strength, cardio, flexibility, HIIT, plyometric).
    - Browse exercises by equipment (barbell, dumbbell, cable, machine, bodyweight, kettlebell, resistance band).
    - Search exercises by name.
    - View exercise detail: name, description, primary muscles, secondary muscles, equipment, difficulty, instructions (step-by-step), tips, common mistakes.
    - Favorite exercises for quick access.
    - Custom exercise creation.

  4.2 Workout Plan Management
    - Create a workout plan with a name, description, and ordered list of exercises.
    - For each exercise: specify target sets, target reps (or rep range), target weight, rest period.
    - Reorder exercises via drag and drop.
    - Duplicate and modify existing workout plans.
    - Delete workout plans.
    - Organize plans into folders or tags (e.g., "Push", "Pull", "Legs").
    - Select from curated template workouts.

  4.3 AI Workout Generation
    - Generate a single workout or a multi-day split (push/pull/legs, upper/lower, full body).
    - Inputs: goal (strength/hypertrophy/endurance), duration (minutes), equipment available, muscle groups to target, difficulty level.
    - AI considers: user's training history (avoid overtraining fatigued muscle groups), personal records (set appropriate weights), and stated preferences.
    - Generated plans are saved and editable like any user-created plan.
    - AI can modify existing plans on request ("Make this harder", "Add more leg work").

  4.4 Active Workout Tracking
    - Start a workout from a plan or as a freestyle session.
    - Navigate between exercises (swipe or buttons).
    - For each exercise, display: exercise name, target sets/reps, previous performance, current sets logged.
    - Log each set: weight input (numeric keypad) + reps input (numeric keypad).
    - One-tap to copy weight/reps from previous set or previous session.
    - Rest timer: starts automatically after logging a set, configurable per exercise.
    - Rest timer: haptic vibration and sound notification when rest is complete.
    - Skip exercise or reorder mid-workout.
    - Add a new exercise mid-workout.
    - Personal record detection: highlight when a set exceeds any previous max (weight, reps, or volume).
    - Workout duration timer running throughout the session.
    - Notes field per exercise for form reminders.
    - Cancel workout with confirmation dialog.
    - Complete workout → summary screen showing total volume, duration, exercises completed, PRs set.

  4.5 Workout History
    - List of all completed workout sessions, sorted by date.
    - Each entry: workout name, date, duration, total volume (weight × reps), exercise count.
    - Detail view: all exercises with set-by-set logged data.
    - Filter by workout plan, date range, or muscle group.

  4.6 Personal Records
    - Track PRs per exercise: max weight for any rep count, max reps at any weight, max volume in a single set.
    - PR history with dates and progression.
    - PR notification badge in the active workout when a new PR is achieved.
    - Strength progression chart per exercise.

=====================================
5. NON-FUNCTIONAL REQUIREMENTS
=====================================

  - Active workout screen must persist state through app backgrounding and process kills (MMKV persistence).
  - Set logging input must respond within 100ms (instant feel for numeric keypad).
  - Rest timer must be accurate to the second.
  - Exercise library search must return results in under 200ms.
  - Workout history must support pagination for users with hundreds of sessions.
  - Offline mode: full active workout tracking without network connectivity, sync on reconnect.

=====================================
6. USER FLOW
=====================================

  6.1 Starting a Workout
    1. User navigates to Workouts tab.
    2. Sees list of workout plans (user-created and AI-generated).
    3. Taps a workout plan → sees exercise list with targets.
    4. Taps "Start Workout" button.
    5. Active workout screen opens with the first exercise.
    6. Workout timer starts.

  6.2 Logging a Set
    1. Active workout screen shows current exercise with target sets/reps.
    2. Weight input shows previous session's weight as default.
    3. User adjusts weight if needed.
    4. User enters reps completed.
    5. User taps "Log Set" button.
    6. Set is recorded with animation. PR badge shows if applicable.
    7. Rest timer starts automatically.
    8. Timer counts down with vibration/sound on completion.
    9. User moves to next set or next exercise.

  6.3 Completing a Workout
    1. User logs all sets for all exercises (or skips remaining).
    2. User taps "Finish Workout."
    3. Workout summary screen displays: duration, total volume, exercises completed, sets completed, PRs achieved.
    4. Optional: rate workout difficulty (1-5 scale).
    5. Optional: add workout notes.
    6. User taps "Save."
    7. Workout session is saved to the backend.
    8. Dashboard and progress analytics are updated.
    9. AI Coach recognizes the completion for future context.
    10. Celebration animation plays (Lottie) if PRs were achieved.

  6.4 AI Workout Generation
    1. User taps "Generate Workout" or asks AI Coach "Create a chest and back workout."
    2. If from Workouts tab: modal asks for goal, duration, equipment, muscle groups.
    3. If from AI Coach: AI infers parameters from conversation and calls generate_workout function.
    4. Generated workout appears with exercises, sets, reps, rest periods.
    5. User reviews and can modify (swap exercises, adjust sets/reps).
    6. User saves the workout plan.

7. TECHNICAL DESIGN
=====================================

  7.1 Exercise Data Model

    Exercise:
      - id: UUID
      - name: string
      - description: string
      - instructions: string[] (step-by-step)
      - tips: string[]
      - common_mistakes: string[]
      - primary_muscles: MuscleGroup[]
      - secondary_muscles: MuscleGroup[]
      - equipment: Equipment
      - category: ExerciseCategory
      - difficulty: 'beginner' | 'intermediate' | 'advanced'
      - is_compound: boolean
      - is_custom: boolean (user-created)
      - image_url: string | null
      - video_url: string | null

    MuscleGroup enum: chest, back, shoulders, biceps, triceps, forearms, quadriceps, hamstrings, glutes, calves, abs, obliques, lower_back, traps, lats

    Equipment enum: barbell, dumbbell, cable, machine, bodyweight, kettlebell, resistance_band, smith_machine, ez_bar, trap_bar, pull_up_bar, dip_bars, bench, stability_ball, foam_roller, none

    ExerciseCategory enum: strength, cardio, flexibility, hiit, plyometric, olympic_lift, calisthenics

  7.2 Workout Plan Data Model

    Workout:
      - id: UUID
      - user_id: UUID
      - name: string
      - description: string | null
      - workout_type: 'strength' | 'cardio' | 'flexibility' | 'hiit' | 'mixed'
      - estimated_duration_minutes: number
      - difficulty: 'beginner' | 'intermediate' | 'advanced'
      - is_ai_generated: boolean
      - tags: string[]
      - created_at: timestamp
      - updated_at: timestamp

    WorkoutExercise:
      - id: UUID
      - workout_id: UUID
      - exercise_id: UUID
      - order_index: number
      - target_sets: number
      - target_reps: number | null (null for time-based)
      - target_duration_seconds: number | null (for timed exercises)
      - target_weight_kg: number | null
      - rest_seconds: number (default 90)
      - notes: string | null
      - superset_group: number | null (exercises with same group are supersetted)

  7.3 Workout Session Data Model

    WorkoutSession:
      - id: UUID
      - user_id: UUID
      - workout_id: UUID | null (null for freestyle)
      - workout_name: string
      - started_at: timestamp
      - completed_at: timestamp | null
      - duration_seconds: number
      - total_volume_kg: number (sum of weight × reps for all sets)
      - total_sets: number
      - total_reps: number
      - calories_burned: number | null
      - difficulty_rating: number | null (1-5)
      - notes: string | null
      - is_completed: boolean

    WorkoutSessionSet:
      - id: UUID
      - session_id: UUID
      - exercise_id: UUID
      - set_number: number
      - weight_kg: number | null
      - reps: number | null
      - duration_seconds: number | null
      - is_warmup: boolean (default false)
      - is_dropset: boolean (default false)
      - is_failure: boolean (default false)
      - is_pr: boolean (default false)
      - rpe: number | null (Rate of Perceived Exertion, 1-10)
      - notes: string | null
      - created_at: timestamp

  7.4 Active Workout State (Zustand + MMKV)

    ActiveWorkoutState:
      - workoutId: UUID | null
      - sessionId: UUID | null
      - workoutName: string
      - startedAt: timestamp
      - currentExerciseIndex: number
      - exercises: ActiveExercise[]
      - isRestTimerRunning: boolean
      - restTimerSeconds: number
      - restTimerTotal: number

    ActiveExercise:
      - exerciseId: UUID
      - name: string
      - targetSets: number
      - targetReps: number | null
      - restSeconds: number
      - completedSets: CompletedSet[]
      - previousSets: PreviousSet[] (from last session of same workout)

    CompletedSet:
      - setNumber: number
      - weightKg: number | null
      - reps: number | null
      - isWarmup: boolean
      - isPR: boolean
      - timestamp: number

    This state is persisted to MMKV after every set log to survive process kills.

  7.5 PR Detection Algorithm

    For each exercise, track:
      - Max weight per rep count (e.g., best 1RM, best 5RM).
      - Max reps per weight (e.g., most reps at 100kg).
      - Max volume in single set (weight × reps).

    On each set log:
      1. Query the user's PR records for this exercise.
      2. Compare the logged set against all PR categories.
      3. If any PR is exceeded, mark is_pr = true and notify the user.
      4. PR records are denormalized in a personal_records table for fast lookup.

  7.6 Progressive Overload Recommendations

    After each workout session, the system analyzes performance against targets:
      - If the user hit target reps for all sets: recommend increasing weight by 2.5kg (upper body) or 5kg (lower body) next session.
      - If the user fell short of target reps by more than 2: recommend maintaining current weight.
      - If the user exceeded target reps by more than 3: recommend increasing weight.
      - Recommendations are stored and displayed as suggestions in the next workout.

9. COMPONENTS
=====================================

  WorkoutCard:
    - Name (headlineMedium), description preview, tag chips (muscle groups).
    - Metadata: exercise count, estimated duration, difficulty badge.
    - Press: navigate to workout detail.
    - Long press: context menu (edit, duplicate, delete).

  SetLogger:
    - Two numeric inputs side by side: Weight (kg/lbs) and Reps.
    - "Log Set" primary button below.
    - Previous set reference displayed above inputs.
    - Auto-fills weight from last set or previous session.
    - PR badge appears next to the logged set if a record is broken.

  RestTimer:
    - Large circular countdown timer (ProgressRing).
    - Time remaining in center (displayMedium).
    - "+30s" and "-30s" adjustment buttons.
    - "Skip Rest" ghost button below.
    - Haptic vibration and optional sound on completion.
    - Background-safe: timer continues when app is in background.

  ActiveWorkoutHeader:
    - Workout name (headlineMedium).
    - Elapsed time (live-updating).
    - Exercise progress indicator ("Exercise 3 of 8").
    - "Finish" button (top right).

  WorkoutSummary:
    - Duration, total volume, total sets, total reps, calories burned estimate.
    - PRs achieved (highlighted with celebration animation).
    - Difficulty rating (1-5 stars).
    - Notes text area.
    - "Save & Close" primary button.

11. API REQUIREMENTS
=====================================

  GET /api/v1/workouts
    Query: type ('mine' | 'templates'), page, limit
    Response: { data: Workout[], pagination }

  POST /api/v1/workouts
    Request: { name, description, exercises: WorkoutExercise[] }
    Response: { data: Workout }

  GET /api/v1/workouts/:id
    Response: { data: Workout with exercises }

  PUT /api/v1/workouts/:id
    Request: Partial workout update.
    Response: { data: Workout }

  DELETE /api/v1/workouts/:id
    Response: 204

  POST /api/v1/workouts/:id/sessions
    Request: { startedAt, completedAt, sets: SessionSet[], rating, notes }
    Response: { data: WorkoutSession with PR highlights }

  GET /api/v1/workouts/sessions
    Query: workoutId, startDate, endDate, page, limit
    Response: { data: WorkoutSession[], pagination }

  GET /api/v1/workouts/sessions/:id
    Response: { data: WorkoutSession with all sets }

  GET /api/v1/exercises
    Query: muscleGroup, category, equipment, search, page, limit
    Response: { data: Exercise[], pagination }

  GET /api/v1/exercises/:id
    Response: { data: Exercise }

  POST /api/v1/exercises
    Request: Custom exercise data.
    Response: { data: Exercise }

  GET /api/v1/exercises/:id/history
    Query: page, limit
    Response: { data: ExerciseHistory[] } (all sets for this exercise across sessions)

  GET /api/v1/exercises/:id/records
    Response: { data: PersonalRecord[] }

13. AI REQUIREMENTS
=====================================

  - AI workout generation must consider: user's fitness level, available equipment, training history (avoid overtraining muscle groups worked in last 48 hours), personal records (set appropriate weights), and stated preferences (exercise dislikes stored in AI memory).
  - The generate_workout function must return a structured workout object that can be directly saved.
  - AI should explain its workout choices when asked ("I chose Romanian deadlifts because your posterior chain is undertrained based on your recent sessions").
  - AI should provide progressive overload recommendations based on the user's logged data.
  - AI can modify existing workouts on request ("Make Monday's workout focus more on chest").

=====================================
14. ERROR HANDLING
=====================================

  - Active workout data loss prevention: state saved to MMKV after every set. On app restart, check for active workout and prompt to resume or discard.
  - Set log with weight 0: allow (bodyweight exercises) but validate reps > 0.
  - Exercise library fails to load: show cached exercises from MMKV.
  - Session save fails: queue in MMKV, retry on next network availability.
  - PR detection fails: degrade gracefully, don't show PR badge.

=====================================
15. EDGE CASES
=====================================

  - User logs a set with 0 reps: reject with inline error.
  - User logs extremely high weight (e.g., 1000kg): allow but confirm with a dialog.
  - App killed during active workout: resume from MMKV state on next launch.
  - User changes unit system during an active workout: convert all displayed values immediately.
  - User deletes a workout plan that has active sessions: orphan sessions remain, linked by workout_name.
  - Exercise deleted from library but referenced in past sessions: soft delete, still display in history.
  - Superset exercises: display side by side and alternate sets.
  - Timed exercises (planks, wall sits): use duration timer instead of reps input.

  - Calculate total volume in real-time during the workout.
  - Pre-fill weight inputs from the last session's data.
